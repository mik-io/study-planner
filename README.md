# Study Agile（仮） - 柔軟な受験勉強スケジュール管理アプリ

## 1. プロジェクト概要・設計思想
既存の学習管理アプリにある「試験日から逆算した機械的な日割りスケジュール」や「1日ごとの事前予定固定」を排除し、受験勉強の実態に即した**ジャストインタイム型の学習計画・進捗管理Webアプリ**。

### コアコンセプト
1. **3階層の連動管理**: 「1〜3ヶ月の長期目標」→「1〜2週間の週間プール」→「毎日のToDo」をシームレスに連動させる。
2. **未来の日付を埋めない**: 週間計画は「今週中に終わらせる範囲の塊（プール）」として保持し、特定の日付には割り振らない。
3. **最低量（フロア）のみ設定し、上限を設けない**: 毎朝その日の体調や予定に合わせて「やるべき最低量」だけを決め、勉強後に「実際にやった量（上限なし）」を記録する。
4. **実績ベースの自動減算**: 勉強後に記録した「実績量」が、自動的に「週間プール」と「長期目標」の残量から差し引かれる。
5. **デバイス最適化**: 週末にPCで長期・週間計画を組み、平日の朝はスマホ（PWA）から15秒で今日のToDo作成・進捗記録を完結させる。

---

## 2. 技術スタック（サーバーレス構成）
起動時のスリープ待ちをなくし、スマホから即座にアクセスできるようバックエンドサーバーは置かず、フロントエンドからFirebaseへ直接接続する。

- **Frontend**: HTML / CSS / JavaScript（または React + Vite）
- **Auth**: Firebase Authentication（Googleログインのみ）
- **Database**: Cloud Firestore
- **Hosting**: Firebase Hosting（または Vercel）
- **PWA**: `manifest.json` 対応（スマホのホーム画面から全画面アプリとして起動）

## 3. 機能要件

### ① 認証・マルチユーザー対応
- Googleアカウントによるワンタップログイン。
- すべてのデータはログインユーザーの `uid` 配下に保存し、将来的に他ユーザー（友人など）へ公開してもデータが完全に分離される構造にする。

### ② 長期計画（1〜3ヶ月スパン）
- 試験日や模試に向けた参考書・教材ごとの全体目標を登録。
- 項目：教材名、単位（ページ / 題 / 章）、総量、目標周回数、現在の周回数、累計完了量、期限日。

### ③ 週間プール（1〜2週間スパン）
- 長期計画に紐づく「今週（またはこの2週間で）進める目標範囲の塊」を設定。
- 未来のカレンダーへの日割り配置は行わない。
- 週の終わりには、未達成の残量をワンタップで次週のプールへ繰り越し・再設定できる。

### ④ 毎日のToDo（朝の作成 ＆ 勉強後の記録）
- **朝のToDo作成**:
- アクティブな「週間プール」の一覧から、今日取り組む教材をタップして選択。
- 今日クリアする**「やるべき最低量（`min_amount`）」**のみを設定する（上限は設定しない）。
- **勉強後の実績記録**:
- タスク完了時に**「実際にやった量（`actual_amount`）」**を入力する。
- `actual_amount >= min_amount` で達成判定とし、最低量を超過した分（貯金分）は視覚的に強調表示する。
- 入力された `actual_amount` 分だけ、紐づく「週間プール」と「長期計画」の進捗がリアルタイムで自動更新（減算）される。

### ⑤ UI / レスポンシブ設計
- **スマホ画面（幅 768px 以下）**: 開いた瞬間に「今日のToDoリスト」と「週間プールからの切り出しボタン」が最上部に表示されるモバイルファースト設計。キーボード入力を最小限にし、タップや数値ボタン（+1, +5, +10など）で操作できるUI。
- **PC画面**: 「長期計画」「週間プール」「今日のToDo」の3階層を1画面で俯瞰・編集できるダッシュボード表示。

## 5. MVP（現在の実装）

まず動作を試せるブラウザ版を用意しています。

- 長期目標（教材名・単位・1周の量・周回数・期限）の登録と進捗表示
- 長期目標から週間プールを作成（期間中の日ごとの予定は作成しません）
- 週間プールから今日のToDoを作成し、最低量と実績量を別々に記録
- 実績量を週間プールと長期目標へ反映し、最低量を超えた分を表示
- 週間プールの未達量を次の期間へ繰り越し
- モバイル・デスクトップ対応、PWA manifest とオフライン用キャッシュ

### 起動方法

静的ファイルを配信できるHTTPサーバーでリポジトリを開きます。例：

```sh
python3 -m http.server 8000
```

ブラウザで `http://localhost:8000` を開いてください。Service Workerによるオフライン機能とホーム画面への追加にはHTTPS（またはlocalhost）が必要です。

### MVPの保存・認証について

現在のデータ保存先はブラウザの `localStorage` です。同じブラウザ内では再読み込み後もデータが残りますが、端末間同期・Googleログイン・Firestoreへの保存はまだ行いません。Firebaseのプロジェクト設定後に、READMEのデータ設計に沿って認証とFirestoreを接続する想定です。
